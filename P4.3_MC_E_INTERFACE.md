# P4.3-MC — MC-E : interface de modération

Date : 16 octobre 2026. Branche : `codex/p4-3-mise-en-conformite`.

**Statut : clôturé localement. Aucun déploiement ni recette staging n'est autorisé par ce document.**

## Périmètre livré

- Console de modération avec les vues « À traiter », « Masqués » et « Traités ».
- Recherche, filtres de période, pagination et conservation des curseurs par vue.
- Consultation du contexte interne du signalement et de l'historique protégé du commentaire.
- Restauration disponible uniquement depuis la vue des commentaires masqués ; décisions masquer, supprimer et écarter conservées.
- Dialogues de confirmation contrôlés : un abandon ou une fermeture n'envoie aucune mutation.
- `expectedVersion` transmis uniquement après confirmation ; un conflit `409` ferme le dialogue, invalide les données de modération et recharge la file sans rejouer la décision.

- `npm run typecheck` : réussi.
- `npm run lint` : réussi sans erreur. Les avertissements préexistants hors périmètre MC-E sont conservés.
- `npm run test:integration -- --reporter=verbose` : **2 fichiers, 7 tests réussis**. Les cinq scénarios dédiés MC-E couvrent l'annulation, la version envoyée après confirmation, le conflit `409`, la recherche et le contexte/historique, ainsi que la restauration depuis « Masqués ».
- `wsl -d Ubuntu-24.04 -- bash scripts/test-backend-wsl.sh` : **23 tests réussis, 0 échec**. Ce contrôle couvre en particulier les contrats API protégés MC-B et MC-D sur lesquels s'appuie la console.

Le journal `api_error` affiché pendant le test de confidentialité simule volontairement une erreur base pour vérifier qu'elle ne soit jamais transformée en succès. Le scénario passe ; ce n'est pas une anomalie de MC-E.
