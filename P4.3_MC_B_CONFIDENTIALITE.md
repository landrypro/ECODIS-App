## Périmètre réalisé

- `mapComment` devient une liste explicite de champs publics sans e-mail ni métadonnées internes. La réponse de création utilise également ce DTO.
- `mapModerationComment` conserve le contrat interne sur les routes protégées ; les types frontend distinguent `Comment` et `ModerationComment`.
- Liste publique : sélection explicite des colonnes, état `visible`, jointure interne sur le parent `published` dans la même requête. Le contrôle initial du parent conserve les réponses 404.
- Compteurs publics : même filtre commentaire visible / parent publié ; aucune métadonnée de jointure dans la réponse.
- Signalement : vérification de publication du parent avant les contrôles d'auteur et de doublon. Les transitions transactionnelles et les courses avec suppression restent du ressort de MC-C.

La syntaxe de jointure a été vérifiée dans la [documentation Supabase](https://supabase.com/docs/guides/database/joins-and-nesting). Aucune dépendance, migration, permission SQL ou configuration distante modifiée. Les guides Supabase et verrou-qualite ont servi à limiter les données sélectionnées et distinguer vérification ciblée et recette complète.

## Tests ajoutés

- `supabase/functions/server/src/lib/comment-privacy.test.ts` : liste exacte des champs publics, absence de données internes même si la ligne en contient, maintien du DTO interne.
- `supabase/functions/server/src/routes/comments.privacy.integration.test.ts` : routes Hono et sérialisation du véritable client Supabase avec transport simulé, sans secret ni appel distant.

Les 14 scénarios HTTP couvrent : lecture anonyme et membre, compteurs, parents draft/in_review/scheduled/archived, refus de signalement hidden/deleted_by_author/deleted_by_moderation, auto-signalement et doublon, signalement valide, parent absent et panne de lecture. Ils vérifient aussi les filtres PostgREST et l'absence de sélection publique par `*`.

Ces tests ne constituent pas une preuve d'exécution SQL ou RLS : la jointure réelle et les permissions seront vérifiées sur base locale en MC-C/MC-D, puis en recette staging. Aucune simulation ne vaut validation des garanties transactionnelles des jalons suivants.
